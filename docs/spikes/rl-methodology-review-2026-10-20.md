# RL 方法论复盘：为什么逐案修补走不通，下一步训练方案

日期：2026-10-20。作者：Claude（审阅 Codex 2026-10-02 → 10-20 的主 session trace、`docs/spikes/` 165 份报告、`out/research/` 753 个研究目录、`docs/benchmarks.md`、`src/ygorl/train/`、`src/ygorl/nets/`，以及外部参照 MirrorForce / VRPO / Ataraxos）。

结论先行：

1. **主循环（PPO 自博弈）从未被证伪，它只是在 10 月 10 日之后停了。** 三种子 u128→u512 的冷/热启动分别 +14.6 / +9.6 pp，平均回合 13.2→9.0；u512 门槛通过并授权更长训练，但此后没有任何一次训练超过 u512。此后两周的全部「实验」都是在冻结检查点上做 16 次更新（1k 行/次，约等于正常训练的 **1 次**更新的数据量）的局部拟合。
2. **逐案修补在当前 regime 下在数学上就不可能收敛。** 当前策略处于严重欠训练状态（数据量是已知可行配方的 1/600、参数量 1/20），检查点之间首选动作一致率只有 59–72%。在这种状态下，「灰自己」「取消循环」「漏斩杀」「攻击目标退化」「Runick 高估」不是五个 bug，是同一个欠拟合策略的五个随机切面；修补其中一个，其他切面会继续随机游走，这就是观察到的「遗忘」。
3. **实验分辨率低于效应量，所以这个循环既不能证实也不能证伪任何东西。** 两周内所有整局对照的效应都在 ±3 pp 内、区间全部跨 0（表 §3）。每个「不显著」又触发下一个诊断，诊断链越拉越长。
4. 建议把工作切回「一个稳定的强度尺子 + 一条长训练主线 + 在主线规模上逐个验证算法改动」，具体方案见 §4。

### 1.2 10 月 10 日之后做了什么

- 426 个 commit（绝大多数是 `docs:` 报告）、450 个「Guardian review」自动 session、753 个 `out/research/*` 研究目录、`out/` 占 360 GB。
- 训练量：每个后续研究 16 次更新 × 1,024 行 ≈ 16k 行；正常一次更新是 16,384 行。也就是说，两周内**没有一次训练的数据量超过主线的一次更新**。
- 典型诊断链（取自 session trace，10-12 一天 70 个 PR）：漏斩杀 → 致死搜索分配 → 阶段配额 → 搜索 RNG → 续局价值 → 首动作交接 → 战斗退出 → …；攻击目标 → 输入缺口 → 重训 4 次更新（实际 7 / 6 个 Adam step）→ Snow/Havnis 单例 head-only 修复 → 梯度审计 → 动量归因 → 2×2 因子……
- 用户在 10-13 问「是否应该修问题然后 retrain，而不是修模型」，10-19 问「是否方法论上不对」。Codex 两次都同意，两次都在下一轮回到局部修补。

读法：要在 95% 置信下分辨 ±2 pp，每臂需要约 5,000 局；这些研究每臂 256–2,304 局。**实验设计的最小可检出效应（MDE）大于任何合理干预的真实效应**，所以结果只能是「不显著」，而「不显著」被当成了「需要再诊断」。

### 1.4 实验方法上的系统性问题

- **标签是 Q^π 不是 Q\***（Codex 10-19 自己指出）：「某局面该不该发动」取决于后续策略；策略一变标签就变。把它固化成监督标签，再要求「保留」，等于要求策略不再改变。
- **测试集变开发集**：同一批卡（Ash、Snow、Havnis、Elf、Neo、Gemini、Stone）反复查看，换种子不能恢复独立性。
- **面板不可比**：retraining-readiness 的面板与 3 种子表的面板不同（同一个 warm u128 在两边是 58% 与 77%）。argmax 与 T=1 采样的结论在不同面板上翻号。
- **评估对手饱和**：对 Greedy 已 84%，再涨 10 pp 也落在噪声里。
- **每个研究都重新搭一套脚本**（`out/research/*/experiment.py`），不走主训练路径；基础设施 bug（监控漏报停机、恢复脚本的种子假设、Colab 回执丢失）本身又消耗了相当比例的轮次。

## 2. 根因：这是一个 regime 问题，不是 bug 列表

### 2.1 与已知可行配方的差距

MirrorForce（tommy85，2026；YGOPro 自博弈，Sky Striker 镜像，击败人类冠军 5–3 / 3–4）是目前最接近的公开参照：

| 项 | ygorl 当前 | MirrorForce |
|---|---|---|
| 策略网络 | d=128，局面 2 层 + 历史 2 层；默认 d=64×1 层，136 万参数（其中 94 万是卡片 ID 嵌入） | 28.1M 参数：状态块 4 层 d=384、回合块 2 层、读出 2 层 |
| 卡片表示 | 结构化列 + ID 嵌入（文本/事实视角未采用） | 78 个数据库特征 + **最多 16 个由 Lua 脚本解析出的效果单元**（64 维哈希语义 token）+ 每卡学习残差；效果投影零初始化 |
| 历史 | 64 个事件 token 的窗口 | 本回合最多 512 行事件 + 过去 64 回合各压成 1 个摘要 token；跨决策持久 |
| critic | 与 actor 共享主干（默认），隐层 128，与 actor 同预算 | **独立 9.4M 中心 critic**，分类 WDL 头，λ=1 回报；达到门槛才切换为优势来源 |
| 优势 | VRPO λ=0.5 | GAE λ=0.5 于 P(win)−P(loss)；**只保留 \|A\| ≥ 75 分位的决策** |
| 正则 | 熵 0.05 固定 + KL 到 EMA 参考 0.05 | KL 到均匀分布的「磁铁」，温度 0.05/(s+1)^0.3；KL 到行为策略 0.1；lr 0.5/(s+1)^1.1 衰减；EMA 0.999 |
| 数据量 | u512 = 840 万行 ≈ 5.6 万局 | ≈ 53 亿决策（1,080 轮 × 490 万） |
| 算力 | 1 块 Radeon 8060S 核显 + 32 核，约 1,085 行/s | 32 × H20 × 3 天 |
| 战术修补 | 持续两周、每轮几个局面 | **只在第 1,000 轮做了一次**：96 个脚本场景（62 训练 / 34 留出），lr 1e-5，交叉熵 + 0.25·KL 到冻结父模型，448 步；然后恢复自博弈 |

MirrorForce 的战术修补与 Codex 做的事在形式上几乎一样，区别只在**顺序**：他们先把策略训到强（1,000 轮 ≈ 50 亿决策），再做一次修补；我们在 5.6 万局的策略上反复修补。

### 2.2 为什么欠训练策略上的修补注定被「遗忘」

- 平台期诊断（09-26）已测出：相隔 600 次更新的检查点首选动作一致率 72%，单批梯度余弦 +0.10。策略本身是一个在随机游走的估计量。
- 修补一个局面 = 在高维参数空间里推一个点；下一次 PPO 更新的噪声步长比修补的位移大。「32 次 PPO 后灰自己从 1.4% 漂回 12.9%」不是干扰，是回归均值。
- 所以「保留旧能力」类方法（回放蒸馏、KL 锚、GEM/PCGrad、逐样本下限）在这里解决的是错误的问题：它们假设旧能力是稳定的、值得保留的；而当前旧能力本身就是噪声。回放把 KL 降了 60% 却不保函数（10-20 诊断），正是这个原因。

### 2.3 真正的结构性缺陷（值得在系统层修，而不是模型层）

这些是环境 / 编码 / 算法层面的真缺陷，修一次就永久有效，和模型无关：

1. **观测缺口**：选攻击目标时看不到刚选的攻击者（已修，#414/#424）；选择历史缺失导致重复决策输入逐字节相同（已修）。这类缺口应继续用「同一真实局面、不同前置动作 → 输入张量必须不同」的性质测试系统性地扫，而不是等某张卡暴露出来。
2. **动作空间病理**：取消 / 反选 / 素材重入循环。正确的位置是环境规则（`UndoRules`、取消预算）并在**训练时就默认打开**，而不是评估时套、训练时关（10-10 的实验证明关了就回来）。决策数上限 6,000 本身也太宽，让循环局占用大量行。
3. **critic 看不到终局**：λ=0.5 时隔 10 个决策终局权重 ≈ 0.001；critic 对真实胜负的解释方差 0.28–0.36，而同策略续局估出的上限是 0.53，差距最大在第 3–4 回合（0.10 对 0.54）。critic 与 actor 共享主干、同样小、同样少的训练步。这是「Runick 牌库耗尽仍 V=+0.43」「LP 变化就能把 V 从 0.41 拉到 0.03」的直接原因。
4. **历史窗口 64 个事件短于现代游戏王的一个回合**（先攻展开 30–80 个决策、事件更多）。策略在回合后半段已经看不到回合开头做了什么。
5. **卡片表示靠 ID 嵌入**：种族成为适配头里最大的 Shapley 项（「种族捷径」）正是因为结构化列里种族是最强的可泛化信号，而 ID 嵌入在 5.6 万局里学不出效果语义。用户 10-15 提出的「从卡片效果代码推导结构化文本」正是 MirrorForce 的做法。
6. **评估尺子不稳定**：没有一个跨研究固定的参考集与样本量。

## 3. 外部参照（经核实的来源）

- **MirrorForce**（github.com/tommy85/MirrorForce，`docs/training.md`、`docs/model.md`、`docs/features.md`）：数字见 §2.1。其搜索模块「尚未显示可测收益」，与本仓库致死搜索阶段 A 的结论一致。
- **VRPO**（Fan & Farina, arXiv 2605.19235）：本仓库 I2 的依据；中等 / 大型博弈上优于 GAE。注意他们的 critic 是独立的中心化 Q critic，不与 actor 共享主干。
- **Reevaluating Policy Gradient Methods for Imperfect-Information Games**（Rudolph et al., ICLR 2026）：7,000 次运行，调好的 PPO / MMD 不输 FP / DO / CFR 类方法。换算法家族不是当务之急。
- **Ataraxos**（Sokota et al., Nature 2026，Stratego，约 $8k 算力）：带磁铁的正则化策略梯度 + 信念网络 + 测试时搜索；MirrorForce 的 KL 温度调度直接采用它。
- **Big 2 自博弈**（arXiv 2605.28863）：同预算下当前策略自博弈优于检查点池与固定对手；适度熵正则有效。
- **Gin Rummy**（arXiv 2607.06854）：非势函数的密集奖励有害；信任域、热启动、keep-best、渐强对手有效。与本仓库 reward-signal.md 的结论一致，**不要再碰回合惩罚**（已测：错误攻击让平均回合 −3.5 的同时条件胜率 −51.6 pp）。

## 4. 方案

原则：**先把尺子立住，再把主线跑长，所有算法改动只在主线规模上做 A/B，诊断链最多一步。**

### P0. 强度尺子（1–2 天，先于一切）

- 固定参考集：`greedy`、BC128、cold u512、warm u512，之后每个里程碑检查点追加；固定 md-2026-09 的 20 套牌配对、四重配对、固定洗牌种子池。
- 每格 ≥ 2,048 局；主线检查点每 256 次更新进矩阵一次；同时报 argmax 与 T=1。
- 行为指标随矩阵一起出：平均回合、每局取消数、截断率、**漏斩杀率**（用现成的 `lethal:` 搜索器在评估局上做离线 oracle，只统计、不干预）。
- 预注册：任何改动声称有效，须给出 MDE 与局数；MDE < 2 pp 的研究每臂 ≥ 5,000 局，否则不允许写「有收益 / 无收益」的结论，只能写「未检出」。
- 用 alpha-rank / Nash 排名作主指标，对 Greedy 胜率降为辅助（已饱和）。

### P1. 长训练主线（立即，和 P0 并行启动）

- 从 cold u512 与 warm u512 各续训一条，目标 ≥ 5,000 次更新（≈ 8,200 万行，本机约 1 天；一周可到 u20k+）。本机 1,085 行/s，Colab L4 约 1.7 倍，用于第二种子。
- 训练内默认打开：取消预算、`UndoRules` 全部规则、决策上限降到 2,000（循环局本来就是截断）。
- 其他一律不改（这是对照）。这条线是之后所有改动必须打败的基线；它也直接回答「主循环是否已经饱和」——目前没有任何数据回答过这个问题。

### P2. 在主线规模上逐个验证的算法改动（每项 1 条线、≥ 2 种子、与 P1 同预算）

按预期收益 / 成本排序：

1. **独立、更大的 critic + 终局目标 + 切换门槛**：`--separate-critic`，d 256、3–4 层；WDL 分类头；critic 目标 λ=1 的终局（优势仍 λ=0.5）；critic 每次更新多走 2–4 倍 minibatch；**只在 critic 对留出局的终局 EV 超过共享 V 头后**才把它接进优势（MirrorForce 的 gate）。09-28 的 λ=1 负结果是在小共享 critic 上测的，不能外推。
2. **优势过滤**：丢掉 |A| 低于 75 分位的行（约 60% 的非强制决策其实接近强制）。一行代码，直接提高梯度信噪比。
3. **正则调度**：熵 0.05 固定 → KL 到均匀分布、温度 0.05/(s+1)^0.3；KL 到行为策略 0.1；lr 1e-4 → 按 (s+1)^−1.1 衰减，下限 5e-6。平台期时策略「一直在动」正是因为没有退火。
4. **卡片语义特征**（用户 10-15 的方向）：从 `CardScripts` 的 Lua 解析效果单元（category / code / range / condition / operation 的 token 哈希），每卡 ≤ 16 单元 × 64 维，冻结；保留小的 ID 残差；效果投影零初始化（热启动不改变行为）。这替代当前的适配头 / 路由器路线，一次性解决「种族捷径」和新卡泛化。
5. **历史**：事件窗口从 64 提到本回合全部（≤ 512）+ 过去回合摘要 token；GTrXL 已有记忆机制，改动在编码器与 `history_mem_len`。
6. **网络放大**（d 256、4+2 层，~10M）只在 P1 数据量 ≥ 1 亿行之后测。09-27 的结论「大网络不更强」是在 650 万行上得到的，数据受限时小网络赢是正常现象。

### P3. 战术盲点：一次性场景修补 + 中局开局，而不是持续补丁

- 建场景库（斩杀、攻前清场、己方效果不自否、目标选择、持盾时机），每族训练 / 留出分开，所有场景由脚本在引擎里打出并校验终局。
- 只在主线每个里程碑（例如每 5,000 次更新）做**一次**监督通过：lr 1e-5，交叉熵 + 0.25·KL 到冻结父模型，整场景采样、族间均衡；验收 = 留出场景改善 ∧ P0 矩阵不下降。不通过就丢弃，不再二次修。
- 更根本的做法是把这些局面变成**中局开局**（设计 I7 / DAGS，引擎快照已有）：以 10–20% 的比例从场景库与漏斩杀局面开局，让终局奖励自己教。这样标签是当前策略下的 Q^π，不会与后续训练冲突，也不需要「保留」机制。

### P4. 流程约束

- 一条诊断链最多一步：诊断 → 直接在 P1 规模上 A/B；不做第二层诊断（梯度投影、动量归因、Shapley 分解这类只在 A/B 为正之后才有意义）。
- 任何「修复」在合入前必须同时给出：性质测试（环境 / 编码层）或主线 A/B（模型 / 算法层）；不接受只有单局面证据的改动。
- `out/` 清理：研究目录的 JSON 轨迹压缩归档，`.pt` 只保留矩阵引用的检查点。
- 文档：每个研究一份报告即可，不按轮次拆 PR。

### 预期

- P1 一周内给出主线学习曲线；若 u512→u5k 继续上涨，说明之前两周的「平台」只是没训练。
- P2.1–2.3 是低成本高把握的改动，预期各 +2–5 pp（在 P0 的尺子上可检出）。
- P2.4 / P2.5 是中等工程量，但它们解决的是用户已经反复点到的两个本质问题：策略看不懂卡、看不全回合。
- 长局 / 漏斩杀 / 自否定这些症状，预期随 P1 + P2.1 大部分自行消失；残余的用 P3 一次处理。

## 5. 本地吞吐实测（2026-10-20，AI Max+ 395 / Radeon 8060S）

`tools/bench_train.py`，u512 配方（md-2026-09 的 20 套牌，d=128、局面 / 历史各 2 层、minibatch 2,048、2 epoch、lr 1e-4），5 次更新取后 4 次平均；原始记录在 `out/claude-scale/bench.jsonl`。

读法：

- **有效的只有两项**：bf16（这块核显没有调优过的 fp32 GEMM 内核，收集与更新同时加速 1.7–2 倍）和优势过滤（更新 20.7 → 12.4 s；minibatch 不变时优化器步数 16 → 4）。两者叠加 2.4–3 倍。
- **无效**：环境数 128 → 1,024、引擎线程 2 → 4、冻结 ID 嵌入，都在噪声内。收集稳定在 5–7 s，不随引擎线程变化，瓶颈在推理 / 编码 / Python 调度而不是引擎；要再提收集速度得先 profile。
- `--overlap` 只在 128×128 且更新已缩到 3–4 s 时有益（1,757 行/秒），在 1024×16 反而更慢。
- 优势过滤改变了每次更新的优化器步数；A/B 里过滤臂用 minibatch 512 保持 16 步，否则比较的不是同一件事。

正在跑的对照 `out/claude-scale/ab1/`：从 cold u512 seed 0 各续训 512 次更新，A = 原配方，B = adv_keep 0.75 + minibatch 512 + bf16；每 64 次更新存一个检查点，用 `out/claude-scale/panel.py`（与 u512 研究相同的 64 组配对 × 4 个对手）评估，可直接与 cold u512 的 84.16% 比较。

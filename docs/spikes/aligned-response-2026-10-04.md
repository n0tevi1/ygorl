# 回应老师：部署采样对齐与简单基线（2026-10-04）

基点 `72dd94d`，分支 `codex/aligned-response`。跟踪 #61 / #62 / #83，脚本性能探索另记 #169。
原始产物：`out/research/aligned-response-2026-10-04/`；运行命令保存在其中的 `run.sh`。
正式采样/评测实现为 `9f98d99`（运行输入与源码完整指纹见两个 manifest）；独立审计工具在 `f6bfb79` 加入。
随后修正了采样工具在**奇数**续局预算下的“至少一半共同有效”取整边界，并加入整组剔除回归测试；本轮固定 32 次续局不受影响。

## 问题与固定协议

上一轮公开 ridge 在局面续局中 +2.59pp，完整外部对局却为 −1.28pp [−3.35,+0.79]pp。
本轮检验更贴近部署的标签能否迁移，并用简单发动倾向对照判断是否值得采用复杂老师。设计先行见
[策略设计](../design/03-play-policy.md) 的 2026-10-04 协议；正式结果前已登记到 [#62](https://github.com/n0tevi1/ygorl/issues/62#issuecomment-5983370700)。

- 候选 BBL05-u400，固定外部对手 seed1 / league / long，md-2026-09 的 20 套合法 meta 牌组。
- 训练 seed=2026100401，32 个四局配对 × 3 对手，共 384 个基础游戏；只取候选自己前四回合内第一个合格回应窗口，最多 8 个合法动作且含 pass。
- 每候选 32 次共同随机数续局，全部作为训练标签，不用训练均值宣称收益。代价/对象与后续动作仍跟随原策略。
- 公开 actor 表征 ridge 正则固定 10；pass-bias 从 `[-4,-2,-1,0,1,2,4]` 以训练结果选择。
- 训练采样出错、或任一局面的共同有效续局不到一半，跨对手剔除整个训练 pairing；无窗口游戏贡献零干预收益。最终测试也使用所有策略共同完整的 pairing。
- 测试 seed=2026100402，128 配对 × 4 游戏 × 3 对手 × 4 策略，共 6,144 完整局。策略为原采样策略、ridge、训练选定 pass-bias、总是发动（取原 actor 概率最大的非 pass）。每局至多干预一次。
- 主检验 ridge−control 点差 ≥2pp 且 95% CI 下界 >0。另对三个干预臂 vs control、ridge vs 两个简单规则共五个预定比较报告 Bonferroni 99% 区间，控制全族错误率。固定样本，不追显著追加，不因测试赢家直接扩训练。

这同时改变老师的数据量和窗口/对手分布，不能唯一识别哪个因素导致变化。对手快照相同、游戏种子独立，也不是未见对手泛化测试。

## 实现与验证

`tools/collect_response_panel.py` 保存候选窗口观测、精确动作前缀、每次续局与来源指纹；完整矩形原子保存，可恢复。
`response_window` 由收集与部署共用；公开推断不读取特权张量。`tools/evaluate_response_reranker.py` 增加两个简单规则与预定比较。
四个策略复用按玩家决策计数的随机流；对照不改变动作，但记录同窗口的三种建议。

冒烟用 seed=2026100400，2 配对 × 3 对手：19/24 局有窗口，四个策略共 76 个干预窗口的完整观测哈希与收集局面一致。
该小样本只验证流程，不报告策略有效性。单测检查非连续动作索引、合法性/回合约束、公共信息边界和跨策略共同剔除。
最终全套本地检查：1,364 passed / 8 skipped（293.60s）；真实 ROCm 上 `tests/test_gemm.py` 6 passed，包含沙箱跳过的 5 项 GPU 测试。
合计覆盖 1,369 项不同测试，剩余 3 项为网络 opt-in 和快照前置条件。GPU 冒烟另行实际完成，lint/format 通过。
共享 ROCm 虚拟环境在沙箱内需要可写缓存：`NUMBA_CACHE_DIR=/tmp/ygorl-numba-cache`、`YGORL_CACHE_DIR=/tmp/ygorl-cache`；
未设置缓存目录的一次复核有 32 failed / 15 errors，定位缓存写入限制后完整重跑通过（`presubmit-corrected.log`）。
GitHub 未生成 hosted CI checks，不把本地通过写成 hosted CI 通过。
`tools/audit_response_panel.py` 检查四组干预前观测/选择一致性、相同动作的终局记录一致性与缺失结局的有限面板上下界；
96 局冒烟通过，刻意修改一个观测哈希时按预期拒绝。该工具核对已保存的终局字段，不宣称没有保存的完整轨迹逐字节一致。

另准备训练集内的探索性逐配对留出诊断（`crossfit_training.py`）：每折使用其余配对拟合相同 ridge 与 bias，然后在留出配对的续局标签上评分。
它不使用最终测试集、不改变已冻结老师或超参数。不同折训练集重叠，因此只作过拟合线索，不给伪独立的置信区间，也不用它替代完整对局验收。

## 训练标签与独立完整对局结果

训练采样已结束（约 34 分钟）：384 基础游戏中 324 个有窗口（seed1 / league / long 为 107 / 112 / 105），
22,784 次续局中 301 次脚本错误。错误集中于 pairing 30（268 次）与 pairing 4（33 次）；按共同有效续局门槛排除整个 pairing 30。
剩余 31 配对、312 窗口、376 个非 pass 动作差标签。308 个窗口有全部 32 个共同有效续局，另外四个为 16 / 27 / 29 / 25。
合法动作数原始分布为 265 个二选一、54 个三选一、5 个四选一。使用窗口的回合分布 T1/T2/T3/T4 为 139/134/25/14，
链长 0/1/2 为 145/166/1。仍主要覆盖早期回应，不是长连锁、完整代价/对象优化。

训练选择的 pass-bias = −4。训练内 ridge 估计 +2.59pp，逐配对留出 −0.20pp；bias 为 +0.48pp、总是激活 +0.68pp。
这些是训练根局面的探索性续局诊断，不能当作冻结策略的独立完整游戏收益。ridge 的训练内/留出差距提示过拟合风险，
没有用这个结果调正则或修改老师。错误按候选共同剔除仍可能造成选择偏差，因此继续保留 #169。

冻结完整对局测试已结束：6,144 局，17 次脚本错误（control 5，其他各 4），共同剔除 pairing 49 / 54，
保留 126/128 配对、每策略 1,512 局。control 得分 50.46%，ridge 51.26%，bias 49.87%，总是激活 50.23%。

| 预定比较 | 配对差 | 点对点 95% CI | 五比较校正 99% CI |
|---|---:|---:|---:|
| ridge − control | +0.79pp | [−1.36,+2.94]pp | [−2.02,+3.60]pp |
| pass-bias − control | −0.60pp | [−2.35,+1.16]pp | [−2.88,+1.75]pp |
| 总是激活 − control | −0.23pp | [−2.22,+1.79]pp | [−2.88,+2.45]pp |
| ridge − pass-bias | +1.39pp | — | [−0.89,+3.74]pp |
| ridge − 总是激活 | +1.03pp | — | [−1.09,+3.21]pp |

**未通过事先设定的 ≥2pp 且 95% 下界 >0 门槛；不扩大该老师，不启动其 PPO 蒸馏。**
简单“更常发动”规则也未测出收益，ridge 没有在校正后显著胜过简单基线。不能据此证明三者等效、所有回应老师无效，
或证明新老师比上一版更强（两次测试种子/数据量不同，没有共同控制下的直接比较）。

审计覆盖 1,536 个基础游戏：1,362 个有合格窗口，四组共 5,448 个窗口的完整观测哈希、原采样动作与三种建议全部一致。
相同干预动作下的 3,574 次比较中，所有已记录的终局字段一致。ridge / bias / 总是激活分别改了 814 / 569 / 684 个动作。
恢复验证复用全部 12 格、零新增对局，summary 与逐局文件的 SHA256 全部保持一致（`panel/resume-validation.json`）。
若给所有脚本错误结局任意 [0,1] 得分，**这批固定游戏**中的 ridge−control 范围为 [+0.52,+1.11]pp，bias 为 [−0.85,−0.26]pp，
总是激活为 [−0.49,+0.10]pp；这不是抽样置信区间，也不消除系统性错误问题，但即使如此也不能把本批 ridge 点差补到 2pp。
区间只涵盖固定 checkpoints/三个固定对手下的游戏抽样，不包含训练种子或未见对手泛化。

下一步优先把 #169 的同调剪枝候选转为有明确回调边界的语义回归与修复；老师方向先在训练配对内检查容量/正则与完整回应动作表示，
任何新候选必须冻结后使用新的完整对局测试，不复用本轮测试调参。当前 GPU 评测已结束，默认训练配方保持不变。

## 脚本复杂度探索（独立于正式实验）

正式 RL 采样使用原始 CardScripts 与默认指令预算。CPU 侧通过独立 `ScriptDirectory` 覆盖实验，未改子模块或运行时默认行为。
仅把同调检查改为先验当前组合、再递归搜索超集，两个失败点仍超限；没有采用。
另一原型只在 `Synchro.CheckP42` 中剪掉已超过目标等级的普通正等级素材组合；当前组与剩余候选有零等级、特殊同调等级、
自定义素材检查，或存在 `req2` / `reqm` / `Synchro.CheckAdditional` 时退回原搜索。
[隔离补丁](synchro-level-guarded-2026-10-04.patch) 针对 CardScripts `1e28935380407e8f4e5a7edf50875b4b38fe56a6`，
原文件 SHA256 `cacd92d496ab653e6e5f304cb2b38b831e4f6d41ab1e842ffab909a0efb1543d`；补丁后
`c3968eeebcb9caf1f0966ff7f0a2327ebbd5926597fed45f6e7bb384d4edfc8f`。没有安装到默认脚本路径。

旧失败轨迹对照用 5× 预算保证参照可完成；64 个新随机策略对局与两个失败前缀使用默认预算。指令计数按每次引擎调用取峰值，时间来自共享机器，
只用来说明复杂度差异。另一条第 333 次决策的原脚本即使单独给 20× 预算仍中止，**没有该失败点之后的原始完整轨迹可作一致性证明**。
未加最终保护条件的早期原型也能改善两例，但结论以上述 guarded 版本为准。

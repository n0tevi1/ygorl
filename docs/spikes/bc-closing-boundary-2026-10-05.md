# 分离教师动作与合成收尾（2026-10-05）

## 问题与先验协议

覆盖面板的 265 条合法线含 6,060 个 BC 标签，其中 594 来自 Python 合成的被动收尾。
Odion 五条线均拒绝 The Man with the Mark 的免费检索；逐条改为发动后，目标场面和 LP 不变、手牌增加一张。
合法回放用于检验目标存活；它不使自动补的 pass/no/end_phase 成为专家行为。

实现先约定：
- `build_dataset` 默认仅模仿 `step < solver_steps` 的原生搜索前缀，合成收尾单独计入 skipped。
- 无论是否学习收尾，始终验证完整线（含结束回合、目标、响应与 board）；拒绝损坏收尾和越界动作边界。
- 保留显式 `include_synthetic_closing` / `--include-synthetic-closing` 仅用于旧结果复现和配对对照，默认关闭。
- train/heldout 使用相同范围，并在训练报告和 checkpoint 元数据记下该范围。已编码开发样本不能悄悄重贴成新数据。
- 完整自由展开仍评价所有起手并走到 turn2；这项修改不把截断前缀当完整可部署策略，不承诺自动改善胜率。

验证：真实 Odion 收尾的错误 `no` 在默认数据中消失、原生标签逐元素不变；显式旧模式复现原数组；
损坏仅发生在被排除的收尾时依然拒绝。全套通过后再用独立训练/留出做 BC 配方比较。
原 320 手 gate 保留失败。教师覆盖同时记录可达性限制；不再把统一 50% 开发阈值当所有起手的规则上界。

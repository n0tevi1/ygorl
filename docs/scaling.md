# 训练规模与训练信号：现状、先前项目、选项（T4b.6 / T4b.7 / T4e.1）

从零开始的 PPO 自博弈在 4 核 CPU 的预算内进展很小（[benchmarks.md](benchmarks.md)「PPO 步长」及其后的 3 小时续训）。本文记录原因、先前项目的做法，
以及两类选项：**扩规模**（[#60](https://github.com/n0tevi1/ygorl/issues/60)）与**提高每份算力的训练信号**
（[#61](https://github.com/n0tevi1/ygorl/issues/61)、[#62](https://github.com/n0tevi1/ygorl/issues/62)）。
与设计文档冲突的选项都标出来了：它们只作为默认关闭的实验开关，采用前先改设计。

## 1. 现状（2026-09-23，4 核云容器、无 GPU）

| 项 | 数字 |
|----|------|
| 端到端 `Trainer.step()`（默认配置、32 局 × 64 步） | 386–415 行/秒 |
| 收集 | 约 1,300 决策/秒，其中 83% 是网络推理（每次约 16 行） |
| 一次更新（2,048 行，4 轮 × 256） | 3.5–3.8 s |
| 引擎上限（C++ 步进、不带网络，T2.7） | 约 2,900 决策/秒/核 |
| 从零训练 3 小时（单牌组对） | 约 4×10⁶ 个决策、3,800 局；对 Greedy 0.05 → 约 0.15 |

瓶颈在网络的推理与更新，不在引擎。

## 2. 为什么多训练几乎不动

从零训练 680 次更新的指标（每段均值）：每次更新策略都有移动（`approx_kl` 约 0.009），但熵（1.22–1.29）、每局决策数（约 1,050–1,220）、
对自己旧快照的胜率（0.44–0.59）都没有趋势：梯度以噪声为主。原因：

1. **长时程、稀疏奖励**：每局约 1,000 个引擎决策、约 450 个训练行，只有终局的胜负；三小时只有约 3,800 局。
   特权 critic 对结果的解释方差约 0.97，但它看得到对手手牌，大部分解释的是策略改变不了的东西；留给单个动作的信号很小。
2. **关键行为几乎碰不到**：接近随机的策略很少完整地「进战斗阶段 → 攻击 → 选对象」，更少走完长 combo；
   对局约 45–50 回合、多以卡组耗尽结束。策略梯度只能强化试到过的东西（[bc.md](bc.md)「根因分析」对 BC 得出同样的结论）。
3. **单牌组对的不对称**：驾驶 kashtira 未训练时对 Random 就约 0.93–0.95，驾驶 snake_eye 约 0.05–0.25。
4. **自博弈的对手太弱**：早期的对手是接近随机的自己。
5. **评估分辨率**：80 局约 ±0.1、每套牌 40 局约 ±0.15、训练中的 16 局约 ±0.25。

## 3. 先前项目的做法

均为读代码 / README 所得（2026-09-23）；「—」表示本仓库没有对应做法。

| 项目 | 做法 | 本仓库 |
|------|------|--------|
| ygo-agent（sbl1996/ygo-agent） | 规模：README 原文「trained for over 100M games (equivalent to training on 32 4090 GPUs for 5 days)」，`0546_22750M` 约 2.3×10¹⁰ 步；多牌组「typically 8x4090 GPUs and 128-core CPU for a few days」；笔记本 GTX 1650 单牌组约 1,000 步/秒 | 少约 5 个数量级 |
| ygo-agent | 快赢奖励 `greedy_reward`（第 1/3/5/7 回合赢 16/8/4/2，负局对称），步数上限到了按 LP 领先者判胜（环境默认开，`cleanba.py` 训练时关） | —（设计 C3：只用胜负；截断局 0 奖励、critic 自举） |
| ygo-agent | GAE + UPGO、γ = 1、λ = 0.95、每次约 32k 步、1 轮 × 64 个 minibatch、熵 0.01、dual-clip | VRPO（设计 I2）、2,048 行、4 轮、熵 0.05（设计 I1） |
| ygo-agent | 当前策略自博弈；OSFP 变体只在胜率 > 0.55 时把快照加入对手池 | 75% 自博弈 + 均匀快照池，无门槛 |
| ygo-agent | 单选项决策、空连锁、SORT_CARD 由环境代答；选区域仍由策略决定 | 同（`skip_forced`，另有等价动作去重、撤销类空操作） |
| cjiang1209/yugioh-agent | 默认对 greedy 训练；0.01·ΔLP/8000 + 0.005·Δ卡数 的塑形；γ = 0.99 | — |
| DouZero / PerfectDou | 约 10¹¹ / 2.5×10⁹ 帧；PerfectDou 用特权 critic + 「离赢还差几步」的逐节点塑形；1 万个固定发牌 + 轮换座位评估 | 特权 critic、配对评估有；塑形无 |
| Suphx（麻将） | 先监督学习再 RL；学出来的逐局奖励预测器（可学的势函数）；自适应熵目标 | BC → RL 有（[bc.md](bc.md)） |
| Metamon、VGC-Bench（宝可梦） | 塑形奖励；BC 初始化的自博弈最好；熵 0.05 → 0.02 退火 | 熵固定 |
| Gin Rummy 2026 | 塑形无效；信任域、热启动、keep-best、「越来越强的对手」有效 | 热启动、keep-best 有；对手课程无 |

结论：凡是达到强水平的项目，要么有巨大的规模，要么从示范热启动。本仓库的 BC 热启动（[bc.md](bc.md)「补救实验」，b2 → PPO）是同一条路。

## 4. 选项

### 4.1 扩规模（#60）

**GPU 还是 CPU**：现在约 80–90% 的时间花在网络上（收集时的推理占收集的 83%，更新每 2,048 行 3.5–3.8 s），这部分可以放到 GPU；
引擎（C++ 核心 + 编码）约 2,900 决策/秒/核，只能在 CPU 上。本仓库的网络很小（136 万参数），一块消费级 GPU 就能把网络的开销压到很低，
之后吞吐由 CPU 核数决定——大约是「1 块 GPU 配几十个核」的比例（ygo-agent 多牌组的配置是 8 块 4090 + 128 核）。致死搜索 / PIMC、求解器示范、
评估对局也都主要吃 CPU。换成默认的大网络（356 万参数）、更长的事件窗口、信念头与文本嵌入会加重 GPU 的份额，但一块中高端消费级 GPU 应该仍然够。
所以：先加一块 GPU（12–24 GB 显存足够）去掉当前的主要开销，之后按核数扩。

| # | 选项 | 预期 | 代价 / 依赖 | 状态 |
|---|------|------|-------------|------|
| S1 | GPU 学习器 + GPU 批量推理（同机 actor / learner） | 更新从秒级降到约 0.1–0.3 s；收集回到引擎上限附近（约 2,900 决策/秒/核） | 一块消费级 GPU；代码基本可用（PyTorch 设备参数） | 待硬件 |
| S2 | 更多 CPU 核跑环境（16 核台式机、AMD AI Max+ 395 等） | 收集约随核数线性增长（C++ 步进 1→4 线程 3.4 倍） | 16 核数字待补（T2.7，#19）；AI Max+ 395 的核显能否被 PyTorch 使用未验证，先按纯 CPU 机器估计 | 待硬件 |
| S3 | actor / learner 异步解耦（IMPALA / V-trace 类修正） | 推理与更新并行，GPU 与 CPU 都不闲 | 改变设计里的同步 PPO，要先改设计；离策略修正的接口位置已在优势估计的 `λ·c_t` | 未开始 |
| S4 | 多机 actor | 线性扩展收集 | 依赖 S3 | 未开始 |
| S5 | 模型侧提速：卡片 ID 嵌入稀疏更新或冻结（占 136 万参数中的 94 万）、事件窗口、GPU 上的 bf16 | 更新更快 | CPU 上 bf16 已测更慢（[benchmarks.md](benchmarks.md)）；GPU 上重测 | 部分已做（CPU 等价改写约 1.46 倍） |

### 4.3 搜索与 RL 结合（#62）

先做对局时的「致死搜索」兜底，量出上限；值得的话把搜索器搬进 C++ 训练路径当老师（专家迭代，蒸馏进策略）；长期是用信念头采样的 PIMC。
阶段 A 已做（`lethal:<agent>`）：包在 K 外面对 Random 0.910 → 0.925、对 Greedy 0.550 → 0.555，在噪声以内——K 自己已经打得出绝大多数斩杀，
所以只为斩杀做阶段 B 不值得（[benchmarks.md](benchmarks.md)「致死搜索原型」）。

## 5. 评估方法

- 对比一律用同一批对局（`ygorl arena tests/decks` 的 100 个有序配对 × 1 对种子 = 200 局）上的配对差，并给 Wilson 区间。
- Random 已接近饱和（0.9 上下），主要看对 Greedy 与对固定强检查点（b2s、P4o）的胜率。
- 待做：四重配对（先后攻 × 牌组交换）与多种子；一个臂一个种子的结论都要标「单种子」。

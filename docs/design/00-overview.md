# 目标与约束

> 属于 [ygorl 设计文档](README.md)。状态：已评审通过（2026-09-22）。


目标是设计并实现一个**遵循当前环境规则**（当前卡池 + 当前禁限卡表）的游戏王 RL 引擎，覆盖三个能力：

1. **对局（Play）**：给定一套牌组，与其他玩家 / agent 进行决斗。
2. **组牌（Build）**：给定整个卡池与当前环境信息（禁限表、主流卡组、对局数据），探索该环境下的组牌策略，**并且要能探索并实验验证「非版本主流但可能强势」的构筑**（off-meta 发现），而不只是复现 meta。
3. **对手预测（Opponent model）**：对局中为 agent 估计对手的隐藏信息（手牌、主/额外卡组剩余构成、盖牌、牌组类型），作为策略的额外输入与辅助训练信号。

三者互相依赖：评估一套牌组需要一个会玩这套牌的策略，训练策略又需要先有牌组，对手预测又依赖 meta 牌组先验与自博弈数据。方案核心是拆成「**牌组无关的通用对局策略**（内层）」和「**以该策略为评估器的组牌搜索**（外层）」两层，对手预测作为内层网络的子模块，并让各层互相反哺。

已确认的约束：
- **格式**：优先 Master Duel（MD），但架构必须适用于 OCG / TCG 等其它规则 → 「环境」做成一等公民配置。
- **框架**：PyTorch。
- **算力**：按单机（1 GPU + 16~64 核，或纯 CPU 小规模）设计；接口留出 actor/learner 分离的余地，需要时再扩展到集群。
- **引擎**：不以许可证决定，先列需求再裁决（见 [01-engine.md](01-engine.md)）。

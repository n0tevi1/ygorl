# 游戏王对 RL 的独特挑战与应对

> 属于 [ygorl 设计文档](README.md)。状态：已评审通过（2026-09-22）。


| # | 挑战 | 为什么游戏王特别难 | 应对（含调研依据） |
|---|------|------------------|------|
| C1 | **规则不是数据而是代码** | 1.2 万+ 张卡，每张效果独立逻辑（时点、连锁、对象、代替 cost），裁定极多。从零实现不可行。 | 复用 edo9300 核心 + Ignis 脚本；把核心当「询问-应答」黑盒状态机，只写绑定、解码与向量化。 |
| C2 | **动作空间结构化、变长、上下文相关** | 选卡（n 选 k）、选效果、选连锁、选区域、选表示、选素材（等级/阶级求和约束）、是/否、宣言数字/属性/种族……候选集完全由引擎给出。固定枚举动作头（LOCM 145 个、MTG 478 个）在 12k 卡 × 效果 × 对象下不可能。 | **动作即输入**（DouZero / Big 2 2026 / ygo-agent）：每个候选动作编码为 token（含**效果级**描述文本，见 I5），与局面表示点积打分，掩码 softmax。**多选 = 自回归指针 + 掩码刷新**（AlphaStar 单位选择）：每选一张就是一个新决策点，环境在 C++ 侧算出剩余可行集（含 `SELECT_SUM` 的求和约束）并在满足最小张数后加入 Finish 选项。网络无需特殊机制。 |
| C3 | **单回合决策极多、回报稀疏** | 先攻一回合可有 30~80 个决策，只有终局有信号；一步选错整条线崩掉。Balatro PPO 复盘：瓶颈在探索不在容量。 | 主奖励只用胜负（Gin Rummy 2026：shaping 无益）。(a) **先攻展开求解器生成示范**（ygo-combo-solver 搜索最优展开线；战斗决策用启发式 agent 示范补足）→ BC 预热 + 只在第 1 回合的 KL 先验 → RL（I4）；(b) **特权 Q-critic + Q-boosted 优势**降低自博弈方差（I2）；(c) **课程**：单人展开 → 对手只有手坑 → 完整对局，外加中局起始状态（I7）；(d) 事件序列 Transformer 记忆（I6）。 |
| C4 | **不完全信息 + 随机性** | 对手手牌、牌堆顺序、盖卡未知；手坑随时介入；隐藏状态 = ~35 张牌堆排列 + 手牌，远超扑克。 | Deep CFR / ReBeL / Student of Games 需要公共信念状态，在此规模不可行。用自博弈 PPO + **历史条件的非对称 critic**（I9）+ **对手预测模块**（§4.5：监督式信念头 + meta 牌组贝叶斯先验 + 「不响应」证据）。决策时 PIMC 搜索用信念头做确定化采样，留作后期。 |
| C5 | **决策粒度极细、双方交替响应** | 每个动作后对方可能响应；引擎按消息推进而非按回合。 | 环境语义 = AEC：「谁被询问谁决策」，每个 `MSG_SELECT_*` 是一个 step；同一网络以视角玩家为条件处理双方；自博弈时同网络双端推理。 |
| C6 | **卡池巨大且每三个月变化** | 新卡、禁限更新使 one-hot ID 冷启动；MD 卡池落后 OCG。 | 卡片表示 = 结构化属性 + 冻结卡文本句向量 + 效果级文本向量，可学习 ID 嵌入作为可关闭的附加项（DraftFM 2026 无 ID 在未见卡集仍 50–60% top-1；Bertram 2024 在 MTG 未见卡上 55%）。 |
| C7 | **对手分布决定强弱（非平稳）** | 一套牌对 A 强对 B 弱；ByteRL 被针对性击败（Haluska & Schmid 2024）说明纯自博弈不够。 | 当前策略自博弈 + 小规模历史快照池（PFSP 抽对手）+ keep-best（I1）、KL 到慢速参考策略（I8）、平台期加利用者；产出**对局矩阵**与 Nash 混合，而非单一 Elo。 |
| C8 | **组牌是双层优化 + 昂贵含噪黑盒，且要发现 off-meta** | 评估一套牌需数百局；空间 C(13000, 40~60)；先要有会玩的策略；牌组强弱非传递（Bhatt 2018）；直接奖励「与 meta 的距离」只得到怪而弱的牌。 | 内层：牌组条件化的通用策略 + 每候选微调预算。外层：**语义协同图**（脚本挖掘，不依赖比赛卡表）生成候选 + 受限基因型 + 三级评估漏斗（求解器起手分析 → 代理模型 → 真实对局）+ MAP-Elites 带学习型描述符与 Dominated Novelty Search；meta 距离只作过滤/报告维度（§4.4）。 |
| C9 | **环境 bug 与奖励黑客** | 社区脚本偶有错误，agent 会学到「假 combo」。 | 求解器找到的线全部以新鲜重放验证；已知 combo 线回归测试；异常高胜率牌组复核；卡池限定为 Ignis `official/`。 |
| C10 | **规则版本差异** | OCG / TCG / MD 卡池、禁限、部分裁定不同。 | `Environment` 配置显式包含 format、pool、banlist、rule flags、meta decks、version；所有产物绑定版本号。 |
| C11 | **吞吐与状态克隆** | 核心单线程 Lua，每核每秒数千决策；且核心 API 无状态克隆，搜索/中局开局本需从种子重放。 | C++ 线程池向量化 + 观测编码在 C++ 侧；**写监视 arena 快照**（ygo-combo-solver 的做法：只恢复脏页，比重放少 15× 流量）解除克隆限制（I3；首版实现为整段拷贝已用前缀，恢复约为重放的 1%）。单机预算：单牌组 1e8~1e9 决策（天级），多牌组联赛 1e9~1e10（周级，需扩展）。 |
| C12 | **对手隐藏信息推断没有现成方案** | 无 YGO 对手预测论文；「不响应也是证据」但对手可能故意藏手坑，朴素规则会错。 | 自博弈有真值 → 监督式信念头；把「响应窗口且对手放弃」编码为显式 token，让 Transformer 从当前对手群体学到策略相关的后验（BAD / Rebstock policy-based inference / Scrabble rack inference 的思想）；见 §4.5。 |


各条的展开：I1–I9 见 [03-play-policy.md](03-play-policy.md)，§4.4 见 [05-deck-building.md](05-deck-building.md)，§4.5 见 [04-opponent-model.md](04-opponent-model.md)。

# 对局策略：起点与改进

> 属于 [ygorl 设计文档](README.md)。状态：已评审通过（2026-09-22）。


**起点（可移植的设计，不直接依赖其代码）**
- **ygo-agent** `docs/`：观测（卡片 160×41、全局 23、合法动作 24×12、历史 32×14）、13 类动作 + 多选序列化 + Finish 标记、`code_list.txt` 词表、einsum 动作打分。→ 移植编码方案到 PyTorch，但网络与训练循环按下表升级。
- **cjiang1209/yugioh-agent**：edo9300 ctypes 绑定 + 快照池自博弈的新鲜参考。
- **envpool** 的 `Env<Spec>` 异步线程池模式 → 自己用 pybind11 + `std::thread` 实现同等接口，避免 Bazel。**CleanRL** 单文件 PPO 作训练循环骨架。
- nashpy / OpenSpiel `psro_v2`、`egt.alpharank`：对局矩阵 → Nash / alpha-rank。IceYGO/windbot 作可选外部基线（非首期）。

**BC 数据契约（2026-10-04，#88）**：求解器与启发式示范混合前必须核对环境版本与指纹、卡片词表的索引顺序、事件窗口长度。
启发式采样使用所选环境的规则并验证牌组合法性；缺少身份元数据的旧编码数据需要重新生成，不能按数组形状相同就接受。
相同种子的 BC 命令应固定网络初始化和训练随机流。容量对照使用同一份经过校验的数据，不将旧环境数据补标签后当成新环境示范。
求解器批次续跑必须核对完整环境指纹、牌组内容、目标、种子、求解预算及实际代码/引擎/脚本/数据库身份；
不兼容批次或缺少身份的旧输出拒绝追加。手牌编号范围可扩展，已记录错误仍须计入全量汇总及退出码。
同一输出只允许一个写者。固定种子和单线程并不消除墙钟预算导致的搜索差异，容量对照以冻结产物为准。
**展开续接（2026-10-05）**：中间目标线只能提供搜索前缀，不能替代最终目标的示范。
续接搜索使用普通洗牌规则，保存到原线首次不可迁移之处（或 solver 前缀结束），不包含自动结束回合。
前缀和候选解必须属于完全相同的起始局面（双方牌序、核心 seed、玩家规则与规则 flags）；
每条候选独立回放、到回合 2 仍满足最终目标才可进入 BC。源与产物均绑定环境；搜索可回退前缀，结果不保证保留全部中间动作。

**强度评估**（2026-09-25，#83）：对局强度用**策略对局矩阵**衡量。检查点、规则 agent、搜索包装的 agent 在同一批牌组配对上两两对局（两种牌组分配 × 先后攻，公共随机数），
用 Nash 混合与 alpha-rank 排名，不用单一 Elo（C7：克制关系不一定可传递）。之后训练中的检查点可以增量加入同一张矩阵，画出强度曲线。
单一对手（Greedy）的胜率只作辅助：它已接近被打饱和。

**配对验收补充（2026-10-02，#83 / #61）**：比较候选与控制组时，所有行必须使用同一组固定外部对手、同一批牌组/洗牌种子和四重配对。
保存逐局结果，按牌组配对与洗牌种子整体重采样，报告候选减控制组的 bootstrap 区间；不可把跨对手复用的局面当作独立样本。
验收用预先固定的新种子，显式记录环境版本、实际规则、代码与检查点指纹。区间只覆盖固定模型和固定对手下的对局采样，不覆盖训练种子不确定性。
错误局单独计数；有错误的配对在所有比较行中共同剔除，报告剔除数及选择偏差风险。样本内两局配对方差不能解释为「牌组决定胜负的比例」。
有限预算 oracle 搜索是特定程序的实测结果，不是所有合法信息搜索的性能上界；未显著改善不等于不存在有效搜索策略。

**决策时搜索**留作后期插件：PIMC/确定化搜索在 LOCM 2026 上以 51.4% 击败 ByteRL，MAPLE 把采样世界聚合进一棵树；依赖 I3、吞吐与 §4.5 的信念头（作为确定化采样器）。

**回应诊断 pilot（2026-10-02，#61 / #62）**：先在固定 MD 牌组/种子上收集每局第一个对手回合的可选连锁窗口（前 4 回合、含 pass，最多 8 个合法候选）。
对全部候选用共同续局种子打到终局，代价、对象及后续决策仍由原策略处理；这测的是当前 continuation 下的动作价值，不宣称找到最优完整回应线。
每候选 32 次续局分成 16 次选动作与 16 次独立评分；按配对而非单局切分训练/验证。保留原始 obs、动作前缀、特权 critic Q、逐次结果和错误，出现错误的续局种子在该状态全部候选中共同排除。
先比较 critic 动作排序、原策略、pass 和用选择半份选出的 oracle。若有可测动作收益，再检验仅用公开 actor 表征的冻结 ridge 重排器；其训练标签可来自特权续局，推断函数只接收合法观测，不能接收真实手牌/牌序/Q 头。
该重排器是有限数据的诊断基线，非 PIMC 已实现；留出局面收益不足则不扩大蒸馏。固定检查点与局面上的区间不覆盖训练种子不确定性。
局面 pilot 通过后冻结权重，用新 seed=20261004、128 个四局配对对 seed1 / league / long 三个固定外部对手进行完整对局验证。
候选只在自己前 4 回合内第一个符合相同条件的回应窗口应用一次重排，其余动作与对照使用相同采样策略；
推断环境关闭 privileged，记录覆盖与实际改动作率。按共同完整配对 bootstrap，主要指标为三个对手等权胜率差；
预设进入训练的门槛仍为提升至少 2pp 且 95% CI 下界 >0，未通过则保持诊断阶段，不按中途结果追加样本。
外部 panel 未通过后，仅作机制诊断：冻结相同权重与完整对局流程，seed=20261005 / 128 配对换成 pilot 的自对弈对手；
不得把此辅助结果取代外部 panel 的失败验收。


网络与训练流水的落地决定见 [06-architecture.md](06-architecture.md) §5.2。

**完整终局 critic 对照（2026-10-04，#61，实验选项，默认关闭）**：`complete_games`
每次收集每个环境槽的一整局，行为策略在局内固定；按游戏拼接成单列，终局之间不回传，
不把长短游戏裁成同一长度。截断或引擎错误整局排除并计数；全批无有效行则报错，不能无限补采。
两臂都用这一采样方式，唯一配方差异为 `critic_target=lambda` / `terminal`。
后者 Q(s,a) 与 V(s) 直接监督为该行玩家的真实终局 z（赢 +1，输 −1，真平局 0），
不读 Q/V、不作 bootstrap 或控制变量修正；要求 gamma=1、turn_discount=1、无 critic_lam 覆盖。
策略优势仍使用同一 VRPO(λ=0.5)，因此这是 critic 监督消融，不能称纯 MC 策略梯度。
`terminal` 必须搭配完整游戏；默认的固定步数收集和 Expected-SARSA 不变。
首轮按同初始化、同训练种子与同完整游戏预算比较，记录实际行数、更新数和墙钟；
终局 EV 在更新前的新游戏上报告，不能用对各自训练目标的拟合优度替代。
仅以未用于调参的固定外部完整对局评价强度，短预算负结果不代表终局监督的普遍上限。


**部署分布对齐实验（2026-10-04，#61/#62/#83）**：冻结 BBL05-u400，保持 seed1/league/long 三个对手。
训练采样改为候选自己在前 4 回合遇到的第一个合格回应窗口，与完整对局部署共用窗口筛选函数；代价/对象仍跟随原策略。
seed=2026100401，32 个四局配对 × 3 对手（384 个基础局）；全部候选各 32 次共同随机数续局，只作训练标签。
同一配对跨对手共同排除采样错误/有效续局不足的局面，错误从不当平局；无窗口局贡献零干预收益。
公开 actor 表征上的 ridge 正则固定为 10，不用测试数据调参；pass-bias 从 [-4,-2,-1,0,1,2,4] 在训练配对上选择。
冻结两者后，seed=2026100402、128 个四局配对 × 3 对手 × 4 策略（6,144 完整局），比较原采样策略、训练选定的 pass-bias、
总是发动（非 pass 里取原 actor 最高概率）和 ridge。每局至多干预一次，其余决策与对照采用相同的按玩家计数随机流。
主要检验为 ridge−control：点差至少 +2pp 且配对 95% CI 下界 >0；另外报告三个干预臂对 control 与 ridge 对两个简单规则的
五个预定比较，用 Bonferroni 99% 单比较区间控制全族错误率。不凭测试中表现最好的臂直接扩大训练，也不按中途结果追加样本。

该轮已完成：ridge−control +0.79pp [−1.36,+2.94]pp，两个简单规则也未测出收益；五个校正比较均跨零。
未达到扩训门槛，默认策略与 PPO 配方不变。训练内/逐配对留出诊断显示过拟合风险；后续容量/正则选择须限制在训练配对，
新候选冻结后重新使用独立完整对局测试，不能复用此次测试调参。数据、误差处理和实现指纹见
[2026-10-04 报告](../spikes/aligned-response-2026-10-04.md)。
该轮同时改变老师的数据量和对手/窗口分布，不能唯一归因于其中一项；完整对局仍是最终强度尺子。


**终局目标 pilot 后续（2026-10-04，#61/#83）**：两个种子、8,192 训练局与
7,680 外部评测局显示 terminal target 较 matched lambda 对照 −4.56pp [−6.66,−2.46]，
不改变默认目标、不扩训此 MC 配方。lambda 对照较冻结起点的 +6.27pp 是辅助发现，
另用第三训练种子 2026100413（64 更新 × 32 完整局）和独立评测种子 2026100414
（128 四重配对、三外部对手、候选与起点共 3,072 局）确认；≥2pp 且 CI95 下界 >0 才进入更长预算。
这确认的是训练配方整体，不能单独归因于完整游戏收集。见 [实验记录](../spikes/terminal-mc-2026-10-04.md)。

第三种子独立确认已完成：+2.21pp [−0.78,+5.18]，未通过 CI 门槛；共同排除截断后也未通过。
不扩大本轮完整游戏配方或改变默认采样。下一项先用同域、近似等训练行数的固定段采样对照
区分采样方式与 MD 额外训练的贡献，不根据已暴露测试追加样本求显著。


普通洗牌示范可以从空起手直接搜索（`--no-ref --start`），无须先求出 pseudo-shuffle 参考线。
该生成方式首版仅支持 plain；每条候选核对实际起始身份，未解出记录也保存原始起始规则、牌序与 seed。
BC 的展开评估优先使用记录的起始局面，无论是否已有成功线；仅旧缺失起始信息的记录才使用历史重建规则。


完整参考线引导诊断（2026-10-05，#83/#88）：普通洗牌起手可选择保留已验证参考线的 native semantic plan。
显式 opt-in；默认行为不变。两组共用同一完整参考线、实际起手、目标和固定深度，仅切换 `--no-plan`，
不可用 `--no-ref` 作为唯一差异的引导消融，因为它同时取消参考线捕获。参考线必须绑定同一环境、合法卡组、
普通规则及被动对手，完整重放到 turn 2 且满足请求目标；不接受只达到中间目标的示范。
先冻结单一参考线和 16 个新开发起手；此诊断仅评价教师搜索覆盖，不能当作策略强度。
协议与结果见 [完整参考线引导实验](../spikes/lunalight-guidance-2026-10-05.md)。

融合材料引导后续（2026-10-05）：先用已知成功线审计脚本声明与名称获取能力，再在新开发种子上
比较普通搜索和基于 Lua 声明的 recipe/backward 引导。两臂关闭自动 LP serial/reenter，
仅改变材料图距离与反向分解，保持原最终目标、普通规则、深度及时间预算。
不以开发门槛仅差一手为由追加同面板求解；见 [冻结协议](../spikes/material-guidance-2026-10-05.md)。

失败起手可达性诊断（2026-10-05）：对固定 13 个共同失败起手使用 120 秒、无 novelty 剪枝的独立搜索，

### PPO KL guard 的更新边界（2026-10-05）

approx_kl由当前minibatch的forward计算，必须在任何backward/optimizer.step之前检查。
policy更新若该值>1.5*target_kl，当前minibatch及其后全部跳过；不能已知超限仍多走一步。
它是停止启发式，**不是严格KL上界**：刚接受的一步仍可能把策略推过阈值，
末次更新之后的真实KL需独立度量，不能把目标阈值称为保证的策略位移封顶。
critic-only warmup冻结策略参数，不受policy KL guard阻断。关闭guard时更新顺序和预算不变。

日志minibatches只计实际optimizer步数，evaluated_minibatches计forward检查次数；
除grad_norm外loss/entropy/KL等诊断对全部检查的minibatch平均（含最后拒绝的一批），
grad_norm只对实际更新平均。stop_approx_kl保留触发值，未触发为0。
首批即超限时允许0 optimizer步，仍有完整有限的诊断，update计数记一次处理的rollout；
不伪称完成过梯度更新。保留已有EMA更新约定。测试必须拦截optimizer.step验证边界，
而不只检查“比全epoch少几步”。

### GPU续训的随机流（2026-10-05）

PPO minibatch的randperm运行于learner设备，使用该设备的全局torch RNG；它与collector的独立generator不同。
GPU checkpoint的rng必须同时保存CPU torch、collector generator和learner设备的CUDA/ROCm全局状态，
在模型、reference、pool及schedule重建完成后恢复。当前单GPU训练只保存learner设备流，不初始化或修改其它GPU。
CPU checkpoint不调用CUDA RNG API、不新增GPU初始化副作用。旧checkpoint没有CUDA字段时仍能载入，
但缺失的GPU历史随机流无法重建，不声称精确恢复。设备迁移不承诺随机序列可比。
测试需在真实GPU训练/保存/载入后比较下一次randperm、CPU随机数与collector抽样，而不只比权重与更新号。
进行中的引擎对局仍重新开局，默认GPU算子也可能存在数值波动；恢复随机流不等于整段训练轨迹逐位复现。

### 混合精度作用域（2026-10-05修复）

`bf16=True`时，collector与整个PPOLearner.update都必须进入既有bfloat16 autocast作用域；
是否critic-only warmup只改变可训练参数，不能意外关闭更新阶段的混合精度。
当前实现的warm判断在with内、update却在with外，偏离原设计；恢复update的作用域，不改变默认FP32配方。
回归需捕获实际训练forward的logits dtype及autocast状态，包含BF16普通更新、BF16 warmup和FP32控制，
并检查参数/梯度有限。已有“BF16训练能跑完”的测试不足以发现静默回退为FP32。
短诊断须覆盖ROCm Split-K的真实大token路径；不据修复本身承诺BF16加速或强度收益。

补充边界：一次PPOLearner.update内有多次Adam，整个更新作用域必须关闭autocast参数转换缓存，
避免FP32权重被修改后后续minibatch继续读取旧BF16副本。只修缩进仍会留下这一问题。
collector作用域内权重不变，可保留缓存；overlap collector使用独立acting副本。
回归需在每个真实Adam步后将当前作用域的logits与禁用缓存的fresh forward逐元素比较，覆盖至少两步。

2026-10-08独立学习器精度：`learner_precision`可选`inherit`（默认）、`fp32`、`bf16`。
`inherit`保留上述`bf16`同时控制采样和更新的行为，旧checkpoint缺失该字段时同样继承。
显式值只覆盖完整`PPOLearner.update`的autocast，包含warmup、reference/BC prior；采样和bootstrap
仍由原`bf16`控制，权重仍存FP32，更新内继续关闭cast缓存。配置、CLI、checkpoint和benchmark须记录该选择。
该开关用于隔离采样数值变化的速度/强度对照，不改变默认训练配方；实际GPU forward回归须覆盖两个方向的覆盖。

### 共享参数的reference EMA（2026-10-05）

慢reference的更新公式对每个唯一参数/持久buffer恰好执行一次：
`reference <- (1 - reference_ema) * reference + reference_ema * learner`，

运行中的四臂LR对照保持原实现冻结，其旧EMA行为作为结果的共同限制明确披露。

### 跨消息的素材取消循环（2026-10-05）

### 实验性动作风险过滤器（#218，2026-10-07）

首轮实现独立`ActionRiskHead`和有界软过滤函数，不接入PPO或默认agent。
